# 제작 과정과 주요 결정

## 2026-11-19–20 · 공간과 퍼즐 개편

- 실제 국악박물관 전시 사진을 참고해 어두운 진열장·유리·목재·직물·돌·놋쇠 재질과 따뜻한 집중 조명을 구성했다. 곡면 출입구와 악기 몸체, 줄·괘·안족·활·장구 조임줄·관악기 지지대를 추가했다. 사진 파일과 외부 텍스처는 게임에 포함하지 않았다.
- 악기 9종, 장단 4종, 13과제로 확장했다. 후반 악기 과제는 5개 층 중 두 악기를 찾고, 장단은 쉼·소박 묶음·시작점 이동을 복원한다. 무대는 편성·장단·갈래를 함께 맞힌다.
- 정답 시 8개 악기가 각자의 빈 진열장에 나타나고 관람 공간의 문이 열린다. 3D 장단판 직접 클릭과 재생 진행 표시, 무대 편성 표시를 패널과 연결했다. 모바일은 위쪽 전시와 아래쪽 스크롤 패널을 함께 보여준다.
- 정악·산조·시나위 도감과 원자료 링크를 넣었다. 음원은 실제 단음의 교육용 창작 음형으로 명시해 실제 악곡 녹음과 구분했다.
- 추가 실제 녹음 5개와 재현 스크립트, 파일별 출처를 확보했다. 악기를 제거할 때 나머지 층의 재생 시점이 이동하던 오류를 수정했다.
- v1 저장의 첫 세 악기/설정을 보존하고 확장된 장단·무대를 다시 진행하도록 이전했다. 재도전의 복원 기록은 유지한다.
- 자동 검사 20개와 TypeScript/프로덕션 빌드 통과. 브라우저에서 전체 13단계 진행, 복합 무대 조건 재검사, 3D 장단 입력, 모바일 표시와 스크롤을 확인했다. 이번 수정의 공개 배포는 하지 않았다.

## 초기 제작 기록

2026-11-15. 초기 저장소는 README·Git만 있었고 작업 폴더 및 상위 경로에 AGENTS.md는 없었다.

1. 설치·가입 없는 정적 배포를 위해 Vite·TypeScript·Three.js 선택. 런타임 AI·DB 없음.
2. 네 방을 작은 2×2 구조에 연결. 악기 → 장단 → 공연장 순서와 안전 좌표 이동 보조 제공.
3. 국립국악원 디지털 단음의 악기별 제1유형을 확인. 음색이 다른 3악기와 장구 3타격을 확보하고 비슷한 높이·음량으로 가공. 총 1MB 미만.
4. 원곡이 아닌 교육용 합주임을 표시. 파트 누락은 예약에서 해당 악기만 제외. 자동 음원 분리 없음.
5. 공식 세마치 예시 채택. 9칸=9박으로 오해하지 않도록 3소박×3박 표시.
6. 대표 흐름(3D 입장→조사→실제 샘플→정오답→재생·해설→저장)을 연결하고 다른 방으로 확장.
7. AudioContext·마스터 Gain 단일화. 새 재생·닫기·포커스 상실·탭 전환에서 기존 예약 정지. 프레임은 소박 위치 표시만 담당.
8. 메뉴 열 때 키·조이스틱 입력 해제. Pointer Lock 없이 드래그. 축별 충돌 판정. DPR 1.7 이하, 실시간 그림자·반사·후처리 없음.
9. 자동 검사·브라우저 뷰포트·실제 기기 검증을 구분해 기록. 전문 음악 검수·관객 테스트는 별도.

AI 지원: 코드 구현·1차 자료 조사·자산 확보 및 가공 스크립트·문서 초안. 제작자 실제 경험/감상은 대신 작성하지 않았다.

## UI 개편 — 2026-11-15

사용자 피드백: 작은 글씨, 과도한 메뉴·카드, 다음 행동이 불분명한 화면, 반복되는 장식 때문에 이질감이 있다는 의견을 받았다.

- 시작·탐험·퍼즐·결과를 각각의 상황으로 분리했다. 탐험은 전체 뷰포트이며 상시 사이드바·홍보 카드·진행 대시보드를 제거했다.
- 지금 할 일 한 문장과 맥락에 맞는 주 행동 하나를 표시한다. 이동 보조와 설정은 메뉴에서 요청할 때 보여준다.
- 퍼즐은 기준 소리를 먼저 듣고 선택하는 순서로 변경했다. 합주 문제는 두 예시를 들어야 후보가 나타난다.
- 악기 선택·미리 듣기를 같은 버튼으로 통합했다. 장단 반복·초기화는 접을 수 있는 보조 조작으로 옮겼다.
- 본문 16~18px, 큰 버튼, 진한 글씨, 절제된 테두리로 바꿨다. 영문 장식 소제목과 인장·다중 카드·상시 진행률을 제거했다.
- 오디오·문제·저장 형식은 유지했다. 기존 진행은 같은 localStorage 키로 복구한다.

## 완료한 퍼즐 재도전

완료 카운터를 현재 문제 번호로 함께 사용하던 구조를 분리했다. 전시실에 들어갈 때 미완료 상태는 미해결 문제부터, 완료 상태는 별도의 실행 중 문제 번호 0부터 시작한다. 정답은 저장 완료 수를 최댓값으로 갱신하므로 같은 문제를 여러 번 맞혀도 다음 공간을 잘못 열거나 100% 기록을 초과하지 않는다. 정답 직후 같은 문제 재시도, 완료/메뉴의 전시실별 재도전, 복원된 표식 재조사를 지원한다. 전체 초기화는 별도 확인 흐름을 유지한다.
